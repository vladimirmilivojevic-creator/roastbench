# Import formats and roast metrics

RoastBench imports roast logs from **CSV** and from **Artisan `.alog`** files. The same parsers run behind the preview
(`POST /api/roasts/import/preview`) and the import (`POST /api/roasts/import`), so what you see in the preview is what
gets saved.

Example files for both formats are in [`samples/`](../samples). They are synthetic (generated by
`backend/src/main/java/dev/roastbench/demo/SyntheticRoastGenerator.java`), not recorded from a real roaster.

## What the importers do with every file

- Time and events are made relative to **charge** (the moment the beans enter the drum, t = 0). Samples before charge
  are skipped.
- Temperatures are converted to degrees Celsius if the file is in Fahrenheit.
- Samples **after drop** (the cooling tray) are not imported. Everything RoastBench calculates describes the roast, which
  ends at drop.
- Anything the importer had to assume is reported as a **warning** in the preview (for example "CHARGE is not marked; the
  first sample is treated as charge").
- Limits: 5 MB per file, 20 000 samples. Larger or malformed files are rejected with a message that names the line.

## CSV

A header row with a time column and a bean temperature column is required; everything else is optional.

```csv
# title: Colombia Huila medium
# beans: Colombia Huila Washed
# machine: Giesen W6
# date: 2026-10-14T09:15:00Z
# green_weight_g: 1000
# roasted_weight_g: 855
Time (s),BT (C),ET (C),Event
0.0,200.1,250.0,Charge
2.0,188.2,248.3,
...
256.0,150.1,231.5,Dry End
...
```

| Part | Accepted |
|---|---|
| Delimiter | comma, semicolon or tab (detected from the header); decimal comma works with semicolon and tab |
| Time column | `Time`, `Time1`, `Seconds`, `Sec`, `t`, `Elapsed`, `Timer`, `Time2`; values as seconds, `m:ss` or `h:mm:ss`; `Time (min)` means minutes |
| Bean temperature | `BT`, `Bean`, `Bean temp`, `Bean temperature`, `BTC` (required) |
| Environment temperature | `ET`, `Env`, `Environment`, `Drum`, `Exhaust`, `Air temp`, `Chamber` (optional) |
| Events | a column named `Event` / `Events` / `Marker`; labels such as `Charge`, `Dry End`, `Colour change`, `FC Start`, `First Crack`, `FC End`, `SC Start`, `SC End`, `Drop`, `Turning point` |
| Fahrenheit | a `°F` / `(F)` hint in the header, or `# unit: F` |
| Metadata | `# key: value` lines above the header: `title`, `beans`, `machine`, `date`, `green_weight_g` / `green_weight_kg`, `roasted_weight_g` / `roasted_weight_kg`, `unit` |
| Artisan CSV | the first row `Date:25.04.2020<TAB>Unit:C<TAB>CHARGE:00:35<TAB>DRY:04:00<TAB>FCs:08:00<TAB>DROP:10:00` is understood as metadata and event times |

Rows are validated one by one. A bad value produces an error such as `Line 4: invalid bean temperature 'abc'` (the first
20 problems are listed). A bean temperature outside 0 to 350 °C is rejected with a hint to check the unit.

## Artisan `.alog`

An `.alog` file is a Python dictionary literal (single quotes, `True`, `False`, `None`). RoastBench reads it with its own
small parser that **never evaluates anything**: it builds maps, lists, strings and numbers, limits nesting depth, and
reports the line and column of a syntax error. Plain JSON is accepted too.

Fields used (names from Artisan's `ProfileData` type):

| Field | Meaning |
|---|---|
| `timex` | sample times in seconds since the recording started |
| `temp2` | bean temperature (BT); `-1` means "no reading" and the sample is skipped |
| `temp1` | environment temperature (ET); gaps are interpolated, a channel without readings is dropped |
| `timeindex` | indices into `timex` for CHARGE, DRY, FCs, FCe, SCs, SCe, DROP, COOL (`0` or `-1` = not set) |
| `weight` | `[green, roasted, unit]` with unit `g`, `Kg`, `lb` or `oz` |
| `mode` | `C` or `F` |
| `title`, `beans`, `roastertype` | name, coffee and machine |
| `roastepoch`, or `roastisodate` + `roasttime` | when the roast happened |

If CHARGE is not set, the first sample is treated as charge and a warning says so. If the weights contradict each other
(roasted heavier than green) both are ignored with a warning.

## How the numbers are calculated

All times are seconds since charge. The code is in `backend/src/main/java/dev/roastbench/analysis` and has no framework
dependency.

| Metric | Definition |
|---|---|
| **Rate of rise (RoR)**, °C/min | slope of an ordinary least-squares line through the bean temperature samples in a window centred on each sample (default 30 s, selectable 15 / 30 / 60 s). A regression is far less noisy than `(T2 - T1) / (t2 - t1)` on probe data. The chart draws it from the turning point, because right after charge the probe is still cooling down. |
| **Total time** | charge to drop (or to the last sample when drop is not marked, which is flagged) |
| **Turning point** | marked in the log, or the minimum of the lightly smoothed bean temperature in the first four minutes |
| **Dry end** | marked, or estimated as the first time the bean temperature reaches 150 °C (flagged as estimated) |
| **Phases** | drying (charge to dry end), Maillard (dry end to first crack start), development (first crack start to drop), each with duration, share of the roast, temperatures and average RoR (drying is measured from the turning point) |
| **Development time ratio (DTR)** | development time ÷ total time × 100 |
| **Roast loss** | (green weight − roasted weight) ÷ green weight × 100 |
| **Comparison with a reference** | both curves aligned at charge and resampled on a 1 s grid over the time both cover; mean, maximum (with its time) and RMS difference of bean temperature, plus differences of dry end, first crack, drop, DTR, loss and per-phase time and RoR |

Inconsistent data (events out of order, a drop after the last sample, roasted weight above green weight) is rejected with
an explanation instead of producing numbers that look plausible but are wrong.
